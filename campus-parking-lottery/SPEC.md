# 校園車位抽籤系統需求 v1.0

確認日期：2026-10-28；用途：學生手機登記、校方主管現場點擊抽籤。

## 使用者已確認
- 手機跨裝置登記，資料集中管理。
- 行政端匯入正式名冊，以班級、學號、姓名完全一致核對；不接校務登入，不宣稱驗證填表者本人。
- 機車（含微電機）同一組，腳踏車另一組；一人只登記一組。
- 管理端設定各組車格編號及名額，獨立抽籤並隨機排備取。
- 固定登記起訖，截止後由管理員人工點擊一次抽籤。
- 點擊後至少3秒顯示「車位配對中」，隨後一次揭示全部配對。
- 管理端完整總表列正取、備取、班級、學號、姓名、車種、車格或備取序。
- 匯出真正Excel .xlsx及可列印另存的PDF完整名單。
- Gemini 3.1 Pro High設計HTML主體；Antigravity Claude Opus 5.5 Medium優化UI/UX；Codex整合發布GitHub。
- 頁尾：[亮亮營養師 AI研究開發]。
- 使用者補充確認：目前沒有Supabase專案；本次先完成並發布可操作展示版及正式部署套件。正式後端部署不在本次已完成範圍。
- 使用者後續明確改指定：主體由Antigravity Gemini 4 Argon設計；實際設定High。原Google Gemini3.1 Pro High三次無程式交付，Antigravity無3.1 Pro可選。Opus5.5 Medium優化角色不變。

## 實作約束
- GitHub Pages僅放程式、說明與虛構範例，正式名冊不進repo。
- 正式跨裝置使用Supabase Auth/PostgreSQL/RPC；未連線時僅開放明示的虛構示範模式。
- 尚未取得Supabase正式專案；後端部署與正式跨裝置驗收不能冒稱完成。
- 管理員必須通過伺服器allowlist驗證；匿名使用者不得讀名冊、登記總表、完整結果。
- 登記起訖與去重由伺服器控制；學號保留前導零，文字trim及NFC，不模糊匹配姓名。
- 正式抽籤在資料庫交易內以活動鎖防並發，只能完成一次；重載讀取同一結果。
- 安全亂數、無偏洗牌，先隨機學生與車格，再配對，剩餘學生連續備取。
- 3秒為揭示延遲，後端失敗不顯示假成功；抽籤重試讀取已存在結果。
- 匯入前預覽無效/重複資料；防HTML注入與試算表公式注入。

## 驗收
雙車種、超額/不足/零申請、前導零、三欄不符、重複申請、截止前後、雙擊、重新整理、匯出全集、手機/桌面/列印、匿名資料邊界。

- 2026-10-28使用者更名：所有介面及Excel/PDF輸出的車種顯示統一為「機車（含微電機）」；內部motorcycle分組代碼保留。
